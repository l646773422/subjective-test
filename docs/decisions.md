# 已确认的设计决策

当前状态：2026-10-23 用户已要求 Windows 直接加载独立 renders 素材目录、每位参与者重新随机抽帧和视点；先敲定 Windows，再联调安卓，最后打包。当前决策见 [ADR 0002](adr/0002-material-directory-and-participant-sampling.md)。

以下 2026-10-16 条目保留为旧版本历史，其中固定题库与图片入包不再是新实验的默认行为。

1. 独立 Flutter 项目，Windows/安卓均用于正式采集；完全离线，无服务器和账号系统。共用领域、排程、呈现、保存与统计逻辑，平台仅负责目录选择、全屏及防休眠。
2. 采用固定题库而非每人重新抽帧。每序列抽一帧并覆盖全部规定视点，共 20 对正式图片。每对两种次序各一次，每人独立随机排程。
3. 必须二选一才能继续，无答题超时、默认答案或跳题；灰场和图片呈现时间在题库冻结后锁定。
4. 全局两道控制题，保持方案数量，不自动扩充；两道全对才有效。
5. 图片按每帧最大数值迭代目录读取；最大目录出错时报告，不静默回退。读取 gt/renders 同名图片，不加载码流、训练模型或渲染器。
6. 使用校验图片与配置的不可变测试包。相同内容在两端共享相同实验 ID，结果可按 ID 验证与合并；代价是冻结时需要复制所选图片。
7. 应用私有存储、逐题原子替换文件，JSON 为无损备份/合并格式，CSV 为分析明细；避免引入在线数据库，代价是用户需要主动导出备份。
8. 演示数据使用合成测试图，并贯穿界面、题库与结果标记，不产生正式照片级真实判定。源图到位后再联调。

## 通用平台方向补充

2026-10-16，用户要求由项目定义简单的数据与操作规范，随后授权接入 Flutter、通用化界面并保留真实感模板和旧数据兼容。上文固定场景、题量和控制题只约束 schema 1 及真实感模板，通用实验使用 v2 定义。客户端已接入草稿、发布版本和 v2 会话，旧包与旧结果继续由原排程和统计实现处理。新合同见 [数据与操作规范 v2](study-data-v2.md) 和 [ADR 0001](adr/0001-standard-study-source.md)。
