# ADR 0005 已拼 SBS 输入与单眼 Patch

状态：已实施并完成 Windows 真实素材验证，设备融合待实机确认。日期：2026-10-23。

需求：新敦煌素材每个刺激已经将左右眼拼成一张 3840×1080 图，目录为 `frame*/test/{gt,renders}`，目前只准备了一个序列。继续要求四个文件或把完整 SBS 再复制到两个半屏都会产生错误。

## 决策

1. 在现有 `presentation.stereo` 中增加可选 `input:sbs`。`a/b` 仍表示两个先后比较的刺激，每个文件左半为左眼、右半为右眼。省略 input 或显式 separate 沿用 `aRight/bRight`。不向旧定义补写新默认字段，原 schema 1 和 v2 会话保持兼容。
2. 已拼模式每题只解码 A/B 两张图，同一纹理由两眼分别采样半幅，避免拆文件、重复解码和将完整 SBS 二次拼接。宽度必须为偶数，A/B 同尺寸。换题与退出按原逻辑释放资源。
3. Patch 先在单眼宽高范围内抽样，保持中心偏重分布和独立 PRNG。右眼绘制矩形为左眼矩形向右平移半个文件宽度；A/B、两眼和重复轮次共享局部坐标。发布与预览均拒绝超过单眼尺寸的配置。保持包含黑背景的全部合法位置，不引入内容筛选。
4. 已拼模式冻结为 `2afc-sbs@1`、`2afc-schedule@5`，trial.patch 为单眼局部坐标，呈现事件记录双眼实际源矩形，CSV 标明输入格式。新旧版本结果按原 revision 隔离，恢复不重抽。
5. Windows 单页明确区分“3D 双目显示”和“3D 素材如何存放”。3D 负责素材解释及双目 UI/指针；Full SBS 沿用已确认的输出方式。原适配器接受一个或多个已知序列，兼容带/不带 primitive 的目录，只读 PNG 头得到尺寸。已知单眼尺寸恰好两倍宽的完整目录默认识别成 Full SBS，并在页面显示；混合普通和 SBS 素材明确拒绝。任意新数据仍可通过 study.json 显式适配。
6. 提供的双目迁移说明用于确认眼睛顺序和坐标单位。场景基线不能直接换算为 UI 像素，预渲染图不再应用相机偏移或 swap_eyes。UI 默认零视差，指针与控件共面。保留原 Full/Half SBS 输出、连续鼠标映射和图片阶段隐藏鼠标的实现。

## 验证与限制

63 项 Flutter、23 项 Python 测试通过，静态分析无问题。合成像素测试区分两眼颜色并检查完整/局部矩形，排程测试检查单眼边界、采样顺序独立性和落盘恢复；旧 mono、分图双眼、旧面积 Patch 和 schema 1 继续回归。

Windows 原生测试直接读取用户提供的 1,500 组敦煌素材，检查自动识别、单页参数、整图只分割一次、512×320 的双眼对应矩形、双目 UI/指针、4 次作答、8 个图片事件和磁盘恢复。隔离验证证据位于 `validation/packed-sbs-windows/`，不写入用户采集库，不改原图。素材黑背景较多，随机 Patch 可以为纯黑区域。软件绘制通过不等于裸眼设备融合通过，后者仍需设备确认；本轮仅 Windows 调试，不制作发布包。
