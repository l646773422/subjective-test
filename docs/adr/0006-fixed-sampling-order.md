# ADR 0006 固定采样内容与顺序

状态：已实施。日期：2026-10-26。

用户希望预先输入指定数量的帧与视点绑定，让不同参与者使用同一份“伪随机”内容及顺序。用户明确确认仅固定帧、视点和出题顺序；A/B 次序平衡、Patch 每人随机保持不变。

## 决策

1. 保留每人随机抽样，新增 sampling.mode=fixed_order、fixedOrder 有序题目 id 列表及现有 perGroup 数量。执行器只识别题目 id，界面根据 metadata.frame/view 定位素材，保持来源适配和通用执行分离。
2. 列表必须非空、唯一、引用 main 题且逐组数量匹配；分组块要求同组连续，不静默改顺序。固定模式不随机打乱正式题或分组，按列表顺序逐组逐轮测试。练习和控制规则不变。
3. 冻结新排程版本 2afc-schedule@6。参与者种子继续决定 A/B 和 Patch，固定列表不替换会话种子。记录 sample.position，并在 CSV 明确标注固定模式与位置。旧 schema 1 和旧 @1～@5 排程不改动。
4. Windows 同一准备页增加选图方式和每序列的多行填写弹窗，显示可用帧/视点、缺项和重复错误及列表预览。数量改变后要求重新匹配，不自动截断或补齐。成功开始时持久化，取消不生成版本；修改列表隔离为新版本，旧会话恢复仍用原列表。
5. 固定模式提高参与者间内容可比性，但不再从完整候选池为每人独立抽样。保留模式标签和完整定义，避免把固定子集误解为覆盖整个素材池。列表不会自动筛掉黑背景，也不改变实验的演示状态或正式模板要求。

## 验证

验证跨多个种子内容与顺序一致、各轮 A/B 平衡、Patch 保持参与者随机、恢复及新旧版本隔离、宽窄窗口输入与错误提示；Python 与 Dart 校验使用相同合同。原生流程在隔离验证库直接使用真实敦煌 SBS 素材，检查填写六个绑定、完整十二次作答、中断恢复及下一位参与者复用列表。测试专用短计时不会写入用户的实际采集库。
