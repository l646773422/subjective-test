# ADR 0007 裸眼设备使用 Half SBS 输出

状态：已实施。日期：2026-10-26。

用户实机确认，左右两幅 1920×1080 应横向压缩合成一幅 1920×1080 才符合设备输入要求；UI 与鼠标也必须使用相同比例。该确认替代此前 Full SBS 的默认假定。

## 决策

1. 使用既有 half_sbs 绘制路径：每眼先按完整视口的逻辑尺寸排版，再通过统一树变换压至半屏，X 缩放 0.5、Y 缩放 1。图片、Patch、文字、按钮、说明、暂停/退出、完成页面和软件指针均经过相同变换，不单独缩字号。点击按同一变换映射，系统鼠标继续隐藏，图片阶段全部指针隐藏。
2. 新建/新开启的双眼测试与原目录适配器默认显式写 half_sbs。准备页可直接选择 Half 或 Full，生效值显示在参数摘要；Full 仍可用于需要该格式的设备。
3. 原 renders 草稿可能已保存旧默认 full_sbs。准备新会话时，若 metadata.sourceAdapter 为既有 renders 适配器且缺少 stereoOutputPolicy=half-default@1，则新表单默认 Half；成功开始时记录策略标记。后续显式选择 Full 可正常保存，不在重启时反复覆盖。只修改新配置，不改发布快照、已采集会话、抽样、种子或图片指纹。
4. 源格式省略 layout 的旧规范继续解析成 full_sbs，保持旧定义及发布校验兼容。应用新建显式写入 half_sbs，避免修改旧默认值产生隐式重放差异。
5. 当前敦煌源图仍为 3840×1080，按左右半幅分别采样；Half 是显示输出方式，不重写原图。Patch 仍在单眼原始像素范围抽取，左右眼对应位置裁剪后一起压缩。采用统一变换避免画面与 UI 采用不同缩放，也避免软件指针和点击坐标错位。

## 验证

像素与几何测试检查 UI 宽度减半、高度不变，软件指针采用相同横向比例；整图及 Patch 均按对应单眼填满 Half SBS 视口。旧 Full SBS 会话和显式 Full 选择仍能恢复。Windows 原生真实敦煌流程检查输出标记、Patch 实际显示宽高比、双目点击、指针隐藏、完整作答及恢复。
