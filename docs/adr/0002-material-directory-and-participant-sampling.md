# ADR 0002 素材目录独立与每位参与者抽样

状态：Windows 已实施；Android 联调与发布后置。日期：2026-10-23。

用户纠正了原方案：每个序列抽多对，每一对随机帧和随机视点，每位参与者开始时重新抽样；软件与测试素材分离，直接加载给定的四个 renders 目录。该要求取代 ADR 0001 中“所有来源必须先用外部脚本转换”的限制，以及固定单帧题库的默认值。

## 决策

1. 通用执行层仍使用 v2 图片对与相对路径；真实感模板附带 primitive-renders 目录适配器，直接识别用户现有素材。适配规则不进入通用排程与呈现层。
2. 素材库完整索引 5,000 对，不复制 18 GiB 图片。新包只保存规则与清单，物理目录位置保存在本机，导入包后可以重新加载同内容的素材目录。历史自带图片的包继续读取。
3. 新增可选 sampling={mode:per_participant,perGroup:{分组:数量}}；每个会话从各组候选图片对不放回抽取，再对这批图片做两轮次序平衡。旧定义不添加 sampling 默认字段，继续使用原来的固定题库排程。
4. 新抽样采用 2afc-schedule@2；无抽样的 v2 与 schema 1 不改变实现。会话记录种子、实际题目、frame/view 及所选图片 SHA-256。恢复和校验都使用原会话，不重新采样。
5. 目录索引校验配对与覆盖，选中素材才做完整解码和指纹。这样加载不必扫描全部图片内容；代价是未选中的损坏图片在首次抽中时才被发现。不同会话/合并结果的相同路径指纹冲突会被拒绝。
6. 新真实感模板使用 profile 2，候选池允许多帧多视点；profile 1 固定单帧规则仅用于旧版本兼容。随机抽样的统计按序列汇总，不能沿用“每张固定图片至少 15 人”的旧条件。

## 验证

使用合成目录清单检查 120 个种子的抽样覆盖、两轮身份平衡和不相邻约束；用真实四序列原目录做 Windows 原生作答、磁盘恢复与素材独立加载测试。素材、模拟答案和调试产物不进入代码包。详见 [操作与验证](../real-materials-workflow.md)。
