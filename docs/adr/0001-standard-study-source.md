# ADR 0001 统一实验源数据与外部适配

状态：已实施。Flutter 接入 v2，保留 schema 1 读取与复算。

日期：2026-10-16。

## 背景

用户要求将当前真实感评测工具演进为通用主观评价平台，首期只提供 2AFC，并由项目定义简单的数据和操作规范。现有场景名、视点和训练输出目录影响 Dart 与 Android 原生导入逻辑，导致新数据源必须修改应用。

## 决策

1. 平台只接收一种标准源格式：`study.json` 加本目录内被引用的图片。原始数据布局由外部适配器转换。
2. schema 2 使用稳定的 `studyId`、中性的 a/b 素材身份和可选标准答案；具体数据集属性放入不影响执行的 metadata。
3. 作者只填写最小必要字段；客户端展开默认值后发布不可变版本，研究者不管理文件哈希和实现版本。
4. 方法、排程、质量检查和分析分别记录版本。当前只开放静态图片顺序呈现，不建立通用脚本执行器。
5. 保留 schema 1 的包和会话。源数据迁移不能将旧答案重新标记为新排程产生的结果。

数据字段、默认值、发布和结果合同见 [主观评价平台数据与操作规范 v2](../study-data-v2.md)。

## 取舍

统一格式让客户端保持稳定，每增加一种来源需要提供适配器。采用一个 JSON 避免同时维护素材清单、配对 CSV 和配置之间的引用；大量题目交给脚本生成。先保留轻量的 Python 标准库参考工具，暂不引入格式库、服务端和数据库。

额外元数据不会自动改变实验行为。新增方法、呈现能力或统计模型仍需实现相应功能，格式转换不能代替这些实现。

## 备选方案

继续扩充应用内目录识别，会让同一套来源逻辑在 Dart 与原生代码中重复。强制规定图片文件名或 a/b 文件夹虽然直观，但无法完整表达非同名配对、题目角色和标准答案。单独增加 CSV 入口可以在以后作为适配器提供，不成为第二套平台协议。

## 验证

使用完整演示旧包验证转换和逐文件内容保持一致，并用独立最小示例验证无场景、视点和迭代字段的输入。参考工具测试覆盖默认值、可选答案、控制题、排程矛盾、非法路径、丢失文件、重复编号、旧包篡改和禁止覆盖输出。
