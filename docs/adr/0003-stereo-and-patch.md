# ADR 0003 双眼刺激与随机 Patch

状态：Windows 已实施，裸眼 3D 实机融合待验证。日期：2026-10-23。

2026-10-26：本记录中的 Full SBS 默认偏好由 [ADR 0007](0007-half-sbs-device-output.md) 替代；当前设备新测试默认 Half SBS，其他机制保留。

需求是在现有顺序 2AFC 上增加双眼 SBS 显示，以及可关闭、中心偏重的随机区域展示。保持素材独立与旧数据兼容。

## 决策

1. 沿用 `a/b` 作为两种刺激身份；3D 时它们指向左眼，增加 `aRight/bRight` 指向对应右眼。A/B 仍顺序播放，每个刺激的双眼同时播放。显式文件引用优于猜测相邻相机配对；来源转换只需生成这些引用。
2. 可选 `presentation.stereo` 设置 Half/Full SBS、UI 视差和鼠标映射。用户确认设备使用 Full SBS，作为新开启和未指定格式的默认值；既有显式 Half SBS 不变。Half SBS 先按整屏比例排版，再横向压缩到半屏；Full SBS 按每眼视口排版。两眼各绘制 UI，状态和操作共享；滚动同步，禁用单眼按钮悬浮效果。
3. 默认 `pointerMapping:screen` 将整屏输入连续映射到双眼逻辑界面，只向左眼控件分发一次事件；`per_eye` 用于普通屏幕分半点击调试。系统鼠标始终在 3D 测试中隐藏，以同一视差绘制双眼指针；图片阶段隐藏所有指针。2D 图片阶段也隐藏系统鼠标。退出确认、加载、异常、暂停和完成均在双眼界面内呈现。
4. 用户明确选择直接设置像素宽、高，因此新增 `presentation.patch.width/height` 正整数，独立指定尺寸与宽高比；发布前拒绝超过任意候选图片的配置，预览同样检查。按 contain 适应显示，不修改或复制原图。此前 area 配置与已保存会话兼容，原平方根计算和取整算法保持不变；同一配置不能混用两种单位。
5. 随机区域左上角在合法范围使用两个独立均匀随机变量的平均值，得到中心峰值、边缘渐低的三角分布。横纵分别抽样，不用正态截断后夹紧边缘的方法。所有合法位置可被抽中，中心优先不是禁止边缘。
6. 先完成原帧/视点与次序排程，再用 `StableRandom(seed ^ 0x50415443)` 抽 patch，因此开关 patch 不改变同种子的帧/视点选择。每位参与者的每道题只抽一个矩形，A/B、双眼和重复题共享；会话保存像素矩形并在恢复/导入时按冻结算法校验。需要这些能力时，每题所有图片尺寸一致，无法对应的图片明确拒绝。
7. 像素 Patch 使用 `2afc-schedule@4`，旧面积 Patch 保留 `2afc-schedule@3`；立体使用 `2afc-stereo@1`。缺省不写入新字段，旧 @1/@2 排程与 schema 1 保持原行为。独立发布版本隔离新配置与旧结果。
8. 四张图均加载和校验成功后才进入呈现；每阶段在双眼绘制完成的帧回调后计时。出错时不显示半对图片。代价是 3D 每题同时解码四张图片，像素内存约为同尺寸 2D 的两倍；换题和退出释放图片。

## 验证

使用独立合成双眼图验证两种 SBS、两种输入映射、图片阶段隐藏指针、共享裁剪、面积与中心分布、次序平衡、文件变更拒绝、会话落盘与恢复。Windows 原生流程留存双眼截图与呈现事件。合成图只能验证软件输出，设备解码格式、视差舒适度和实际融合仍需裸眼 3D 设备与真实左右眼素材联调。安卓和发布包不在本轮范围。
