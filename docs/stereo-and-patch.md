# 双眼 3D 与 Patch 操作

Windows 调试版支持这两项功能；普通 2D 素材默认关闭，识别出的已拼 SBS 素材默认开启 3D。在首页“开始测试”读取素材目录后，直接开关并设置 Patch / 3D，核对参数后登记并开始，不需要切换草稿和发布版本。已有版本和旧会话继续按原规则运行。需要编辑高级规则时，仍可使用“高级实验管理”中的草稿。完整流程见 [Windows 单页开始测试](windows-start-test.md)。

## 3D 素材

仍是一题两个待比较刺激 A、B，分别先后播放。支持两种输入方式，3D 开关同时控制素材的双目解释、UI 和鼠标。

**左右眼已拼在一张图。**在“3D 素材如何存放”中选择这一项。每个刺激只引用一个文件，左半幅是左眼，右半幅是右眼，不再把同一张完整 SBS 图复制到两个半屏。例如：

```json
{
  "presentation": {"stereo": {"input": "sbs", "layout": "half_sbs", "uiDisparity": 0}},
  "items": [{"id": "frame-012-view-020", "a": "gt/012-020.png", "b": "renders/012-020.png"}]
}
```

以上是完整源描述中的片段。图片宽度须为偶数，同题 A/B 同尺寸。整图模式每眼显示本侧完整半幅；Patch 模式先以单眼宽度抽坐标，再从两侧分别截取同一位置。无需 `aRight/bRight`，也不拆分、复制或重编码原文件。

**左右眼分别存成两张图。**每个刺激用两个相对路径描述，不要求固定文件名或目录：

```json
{
  "id": "frame-012-view-020",
  "a": "left/gt/frame012-view020.png",
  "aRight": "right/gt/frame012-view020.png",
  "b": "left/render/frame012-view020.png",
  "bRight": "right/render/frame012-view020.png",
  "group": "sequence-1",
  "metadata": {"frame": 12, "view": 20}
}
```

分图模式添加题目会依次选择四张图片，四张图片须同尺寸，发布和预览前补齐右眼路径。`presentation.stereo.input` 省略时沿用原来的 `separate` 分图规则；旧定义不会补写这个字段。

原目录适配器同时识别 `frame*/test/primitive/{gt,renders}` 和 `frame*/test/{gt,renders}`，可只选一个序列。已知序列的图片若恰为单眼标准尺寸的两倍宽，则识别为包含完整双眼像素的已拼 SBS 源，页面明确显示“素材：已拼 SBS”；新建测试的输出默认 Half SBS。混合普通/已拼 SBS 的目录会报错。新敦煌目录 `D:/文档/鹏城项目/13专项-沉浸式/项目测试/裸眼` 共 1,500 组，3840×1080，每眼 1920×1080。任意其他命名或分辨率通过 `study.json` 明确声明，不根据相邻视点猜左右眼。

2026-10-26 用户实机确认设备需要 **Half SBS（横向压缩一半）**，替代此前 Full SBS 的假定。新建和新开启的双眼模式默认选择 Half SBS：例如屏幕 1920×1080，每眼按 1920×1080 布局后横向压成 960×1080，再左右合成一屏；高度不变。图片、Patch、文字、按钮、软件指针及点击映射同步处理。左半屏为左眼，右半屏为右眼；每眼只取对应源区域。当前 3840×1080 素材无需重编码。

准备页展开“3D 输出”可切换 Half SBS 和 Full SBS。旧 renders 草稿在首次按新规则准备会话时默认 Half SBS，后续显式选择会随新配置保存。已发布的旧版本和会话保持原输出，不能用新设置改写旧结果。源格式中省略 layout 的旧含义仍为 full_sbs；软件新建规则显式写 half_sbs，兼容解析不变。

提示、问题、选项、暂停、退出确认与完成页面均绘制到双眼。UI 双眼视差范围为 -64～64 逻辑像素，指左右眼的总水平偏移；默认 0，位于屏幕平面。正值向内偏移、负值向外偏移，指针与 UI 使用相同视差。正式使用前在设备上确认可舒适融合。

已阅读提供的《双目相机坐标迁移说明》：相机基线 0.021 属于场景单位，不直接换算成 UI 像素；生成时的 `swap_eyes` 已反映在 SBS 输出顺序中，本软件保持文件 `[left, right]`，不再交换。UI 默认零视差，与鼠标保持同一平面，不对预渲染素材再次施加相机或投影偏移。

默认鼠标映射为“整屏连续”，物理鼠标在整屏的位置对应融合画面的位置，跨过屏幕中线不跳回；点击按双眼软件指针指向的控件生效。普通显示器查看两个半屏时，可以改为“按半屏（调试）”，直接点击任一半屏内的按钮。两种模式一次点击都只触发一次操作。3D 测试始终隐藏系统鼠标，用双眼软件指针交互；**播放图片时同时隐藏软件指针**。键盘 1/2 仍可作答。

## Patch

开启“随机 Patch 展示”，直接填写“Patch 宽 / 像素”和“Patch 高 / 像素”，默认 512×512。宽、高必须为正整数，可以设置任意宽高比。例如 512×320 在 1920×1080 和 3840×2160 原图中都截取恰好 512×320 像素。裁剪结果按自身宽高比等比适应可用显示区域，不改变原文件；关闭则显示整图。

配置尺寸不能超过任何候选图片的宽、高，发布时会指出具体题目和原图尺寸，不静默缩小或拉伸区域。独立预览也会检查越界。旧面积比例配置仍显示为“沿用旧版面积配置”，可点击“改用像素宽高”编辑新规则；已有发布版本与会话继续沿用原面积算法。

对于 3840×1080 的已拼 SBS，尺寸上限按单眼 1920×1080 计算。512×320 表示左右眼各取 512×320，左眼源区域 `(x,y,512,320)`，右眼为 `(x+1920,y,512,320)`。不允许一个 Patch 跨过中线。内容筛选未启用，黑背景较多的素材可能抽到纯黑 Patch；抽样分布仍按位置决定。

每位参与者先抽取随机帧和视点，再对每道选中题抽取一次区域。横纵位置独立采用三角概率密度，中心最高，向两端线性降低；边缘仍有机会被选中。A/B、左右眼与同题各轮使用同一矩形，中断恢复不重新抽取。独立预览不保存会话，每次重新预览会抽新区域。

3D 与 Patch 可以独立开关。配置写入 v2 的 `presentation`：

```json
{
  "mode": "sequential",
  "promptMs": 2000,
  "imageMs": 3000,
  "stereo": {"layout": "half_sbs", "uiDisparity": 0, "pointerMapping": "screen"},
  "patch": {"width": 512, "height": 320, "distribution": "center_triangular"}
}
```

删除 `stereo` 或 `patch` 字段即关闭对应功能。CSV 增加实际裁剪像素矩形、种子和双眼指纹，完整 JSON 同时保存配置与呈现事件。改变 SBS、视差或 patch 设置需要发布新版本；不同版本结果继续隔离。素材与软件仍分离。

普通像素配置使用 `2afc-schedule@4`。已拼 SBS 使用 `2afc-sbs@1` 与 `2afc-schedule@5`，trial.patch 坐标为单眼局部坐标，呈现事件额外记录左右眼实际源矩形，CSV 标明 `stereo_input`。旧 `patch.area` 与 `2afc-schedule@3` 原样保留；同一配置不能混用 area 与 width/height。

## Windows 验证

`test/stereo_patch_test.dart` 检查随机分布、精确像素宽高、尺寸越界、区域与素材冻结、旧面积格式兼容、双眼点击与鼠标隐藏。`integration_test/stereo_patch_test.dart` 在 Windows 原生窗口运行 Half/Full SBS 各 4 次模拟作答，并在一题后中断、磁盘恢复，检查每题双眼图与共享的 128×96 像素区域。使用合成双眼素材，配置提示 80 ms、图片 1200 ms，结果仅用于流程验证。像素版本截图与报告位于忽略跟踪的 `validation/stereo-pixel-windows/`。

2026-10-23 像素配置回归：55 项 Flutter、22 项 Python 测试通过，静态分析无问题。Windows 原生双眼验证涵盖双眼退出确认、连续鼠标点击、四次作答、八个图片呈现事件、八张图片指纹及中断恢复校验。

`integration_test/real_patch_test.dart` 直接读取原四序列 5,000 对素材，抽取 20 对、保存 40 张原图指纹；使用真实 4K 图片和配置的 3 秒图片时长，验证所有选中图片均截取 512×512 像素，以及一次作答和落盘恢复。像素版本证据位于 `validation/real-pixel-patch-windows/`；之前面积版本证据保留在 `validation/real-patch-windows/`。不复制或修改原图，模拟会话不进入用户的实际采集库。

2026-10-23 已拼 SBS 回归：63 项 Flutter、23 项 Python 测试通过，静态分析无问题。`integration_test/packed_sbs_test.dart` 直接读取新敦煌 1,500 组，验证单页参数、整图只分割一次、单眼 512×320 对应裁剪、8 个图片事件、4 次点击作答及中断恢复。真实图片保持配置的 3 秒显示时间，模拟结果在隔离验证库，截图和报告位于 `validation/packed-sbs-windows/`。实际设备融合仍需实机确认。本轮未构建 Android 或安装包。
