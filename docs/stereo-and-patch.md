# 双眼 3D 与 Patch 操作

Windows 调试版支持这两项功能；默认均关闭。进入实验草稿的“03 呈现与排程”配置，预览后发布新版本即可使用。已有版本和旧会话继续按原规则运行。

## 3D 素材

仍是一题两个待比较刺激 A、B。每个刺激包含左右眼图片，用四个相对路径描述，不要求固定文件名或目录：

```json
{
  "id": "frame-012-view-020",
  "a": "left/gt/frame012-view020.png",
  "aRight": "right/gt/frame012-view020.png",
  "b": "left/render/frame012-view020.png",
  "bRight": "right/render/frame012-view020.png",
  "group": "sequence-1",
  "metadata": {"frame": 12, "view": 20}
}
```

开启“3D 双眼 SBS”后，添加题目会依次选择四张图片；题目设置也可直接编辑相对于已加载素材目录的路径。草稿允许暂未补齐右眼，发布和预览前必须补齐。四张图片必须同尺寸。原目录适配器仍将当前 renders 素材作为 2D 图片对读取；没有指定左右眼关系时不猜测配对。

用户已确认设备使用 Full SBS，新建和新开启的双眼模式默认选择 Full SBS，每个半屏等比显示完整的单眼画面，左半屏始终为左眼。既有 Half SBS 配置继续读取；Half SBS 将完整逻辑画面横向压到半屏，由设备解码恢复比例。实际双眼素材目录仍在准备中，可按任意路径组织后补入文件引用。

提示、问题、选项、暂停、退出确认与完成页面均绘制到双眼。UI 双眼视差范围为 -64～64 逻辑像素，指左右眼的总水平偏移；默认 0，位于屏幕平面。正值向内偏移、负值向外偏移，指针与 UI 使用相同视差。正式使用前在设备上确认可舒适融合。

默认鼠标映射为“整屏连续”，物理鼠标在整屏的位置对应融合画面的位置，跨过屏幕中线不跳回；点击按双眼软件指针指向的控件生效。普通显示器查看两个半屏时，可以改为“按半屏（调试）”，直接点击任一半屏内的按钮。两种模式一次点击都只触发一次操作。3D 测试始终隐藏系统鼠标，用双眼软件指针交互；**播放图片时同时隐藏软件指针**。键盘 1/2 仍可作答。

## Patch

开启“随机 Patch 展示”，直接填写“Patch 宽 / 像素”和“Patch 高 / 像素”，默认 512×512。宽、高必须为正整数，可以设置任意宽高比。例如 512×320 在 1920×1080 和 3840×2160 原图中都截取恰好 512×320 像素。裁剪结果按自身宽高比等比适应可用显示区域，不改变原文件；关闭则显示整图。

配置尺寸不能超过任何候选图片的宽、高，发布时会指出具体题目和原图尺寸，不静默缩小或拉伸区域。独立预览也会检查越界。旧面积比例配置仍显示为“沿用旧版面积配置”，可点击“改用像素宽高”编辑新规则；已有发布版本与会话继续沿用原面积算法。

每位参与者先抽取随机帧和视点，再对每道选中题抽取一次区域。横纵位置独立采用三角概率密度，中心最高，向两端线性降低；边缘仍有机会被选中。A/B、左右眼与同题各轮使用同一矩形，中断恢复不重新抽取。独立预览不保存会话，每次重新预览会抽新区域。

3D 与 Patch 可以独立开关。配置写入 v2 的 `presentation`：

```json
{
  "mode": "sequential",
  "promptMs": 2000,
  "imageMs": 3000,
  "stereo": {"layout": "full_sbs", "uiDisparity": 0, "pointerMapping": "screen"},
  "patch": {"width": 512, "height": 320, "distribution": "center_triangular"}
}
```

删除 `stereo` 或 `patch` 字段即关闭对应功能。CSV 增加实际裁剪像素矩形、种子和双眼指纹，完整 JSON 同时保存配置与呈现事件。改变 SBS、视差或 patch 设置需要发布新版本；不同版本结果继续隔离。素材与软件仍分离。

像素配置使用 `2afc-schedule@4`。旧 `patch.area` 与 `2afc-schedule@3` 原样保留；同一配置不能混用 area 与 width/height。

## Windows 验证

`test/stereo_patch_test.dart` 检查随机分布、精确像素宽高、尺寸越界、区域与素材冻结、旧面积格式兼容、双眼点击与鼠标隐藏。`integration_test/stereo_patch_test.dart` 在 Windows 原生窗口运行 Half/Full SBS 各 4 次模拟作答，并在一题后中断、磁盘恢复，检查每题双眼图与共享的 128×96 像素区域。使用合成双眼素材，配置提示 80 ms、图片 1200 ms，结果仅用于流程验证。像素版本截图与报告位于忽略跟踪的 `validation/stereo-pixel-windows/`。

2026-10-23 像素配置回归：55 项 Flutter、22 项 Python 测试通过，静态分析无问题。Windows 原生双眼验证涵盖双眼退出确认、连续鼠标点击、四次作答、八个图片呈现事件、八张图片指纹及中断恢复校验。

`integration_test/real_patch_test.dart` 直接读取原四序列 5,000 对素材，抽取 20 对、保存 40 张原图指纹；使用真实 4K 图片和配置的 3 秒图片时长，验证所有选中图片均截取 512×512 像素，以及一次作答和落盘恢复。像素版本证据位于 `validation/real-pixel-patch-windows/`；之前面积版本证据保留在 `validation/real-patch-windows/`。不复制或修改原图，模拟会话不进入用户的实际采集库。

裸眼设备的输入模式、真实双眼素材和实际融合待实机确认。本轮未构建 Android 或安装包。
