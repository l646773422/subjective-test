# 固定帧和视点列表

Windows 首页“开始测试”读取素材后，在“测试图片怎么选”中选择“固定帧和视点（所有人相同）”。

1. 为每个序列填写本次测试的图片对数，例如 6。
2. 点击该序列的“填写列表”，按测试顺序输入 6 行，每行是“帧号, 视点号”。支持整段粘贴，也接受中文逗号、空格或制表符。
3. 点击“使用这份列表”，在主页面核对列表顺序、对数及总题数，再登记参与者开始。

例如以下列表会依次选取六对素材：

    12, 20
    85, 0
    7, 30
    144, 10
    200, 50
    249, 40

帧号指 frame000012 中的 12；视点号使用素材 metadata.view 的实际相机编号。原 renders 模板的 00001.png 对应视点 10，不应把导出文件索引 1 填成视点号。弹窗显示素材中实际可用的帧范围和视点号；通用来源需要在每题 metadata 中提供 frame、view，帧/视点在同组内须能唯一定位图片对。

填写数量不符、重复、格式错误或素材不存在会明确报错，不能开始。修改对数后需要同步修改列表，软件不会悄悄删掉绑定或补选其他图片。主页面显示的是实际生效的列表。

## 播放与保存

所有参与者按相同帧、视点和顺序测试。原 renders 使用分组块：先按界面序列顺序进入各组，每组每遍都按所填列表播放，再进入下一组。比如单序列六对、测两遍，出题顺序为 1～6、1～6，共 12 次选择。选一遍则共 6 次。

根据用户确认，仅固定帧、视点和正式题顺序。两遍时 A/B 继续交换播放顺序，初始 A/B 顺序仍按每位参与者种子决定；Patch 仍每人独立随机，A/B、双眼及同题重复轮次共享裁剪矩形。中断恢复保持本会话的题目、次序和 Patch。

列表应用后保留在当前表单，首次成功开始时与其他设置一起保存，下一位及重新启动软件后沿用。取消列表弹窗不改变当前配置。修改列表并开始新会话会生成新的冻结版本，已有会话保持原列表。切回“每人随机抽取”后沿用原抽样行为。

## 数据规范

固定模式在 sampling 中增加 fixedOrder，存正式题 id；帧/视点到 id 的适配由界面完成，执行器仍不依赖 renders 路径。以下为描述片段：

    {
      "sampling": {
        "mode": "fixed_order",
        "perGroup": {"scene": 2},
        "fixedOrder": ["frame85-view0", "frame12-view20"]
      }
    }

两道题必须已存在于 items，并属于 scene。固定模式使用排程版本 2afc-schedule@6，不修改旧的每人随机、双眼和 Patch 排程实现。完整 JSON 包含列表和实际试次，CSV 额外标明固定模式与列表位置。

## 验证

2026-10-26：67 项 Flutter、24 项 Python 测试通过，静态分析无问题。Windows 原生验证直接读取敦煌 1,500 对 SBS 素材，填写上面的六个绑定；第一位完成 12 次作答并验证中断恢复，第二位使用同一版本和同一顺序，Patch 仍独立随机。验证使用 80 ms 的测试专用阶段时长，生产设置仍保持配置值；隔离验证库、界面截图和报告位于 validation/fixed-sampling-windows/，不会写入用户的实际采集库或修改原素材。
